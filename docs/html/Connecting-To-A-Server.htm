Connecting to a server

SmtpClient, Pop3Client and ImapClient all derive from MailService, so connecting, securing the connection, authenticating, logging and error handling work the same way regardless of which protocol you are using. This topic covers those common features.

  Tip

Every method that performs network I/O has an Async counterpart (for example, ConnectAsync). The examples in this documentation mostly use the synchronous methods for brevity, but the asynchronous methods are recommended for UI and server applications.

Choosing how to secure the connection

The SecureSocketOptions argument passed to Connect determines whether and how the connection is encrypted using SSL/TLS:

Value

Behavior

None

No SSL/TLS is used. Credentials are sent in the clear unless the SASL mechanism protects them.

SslOnConnect

The connection is encrypted immediately (implicit TLS). Used with the SMTPS (465), IMAPS (993) and POP3S (995) ports.

StartTls

Connects in plain text and then upgrades the connection using the STARTTLS (or STLS) command. An exception is thrown if the server does not support it. Typically used with ports 587, 143 and 110.

StartTlsWhenAvailable

Like StartTls, but silently continues unencrypted if the server does not support STARTTLS. This is vulnerable to downgrade attacks.

Auto

Uses SslOnConnect for the well-known SSL ports (465, 993 and 995) and StartTlsWhenAvailable for any other port.

  Caution

When you know which ports and security options your server supports, prefer SslOnConnect or StartTls over Auto or StartTlsWhenAvailable so that a man-in-the-middle cannot silently downgrade the connection to plain text.

C# 
                    public static void ConnectWithStartTls ()
{
    using (var client = new SmtpClient ()) {
        // Port 587 is the standard "submission" port. The connection starts out as plain-text
        // and is upgraded to TLS using the STARTTLS command. Using SecureSocketOptions.StartTls
        // (rather than StartTlsWhenAvailable) means that Connect() will throw if the server does
        // not support STARTTLS instead of silently continuing over an unencrypted connection.
        client.Connect ("smtp.example.com", 587, SecureSocketOptions.StartTls);

        Console.WriteLine ("Secure: {0}", client.IsSecure);
        Console.WriteLine ("Protocol: {0}", client.SslProtocol);
        Console.WriteLine ("Cipher suite: {0}", client.SslCipherSuite);

        client.Disconnect (true);
    }
}

After connecting, the IsSecure, SslProtocol and SslCipherSuite properties describe the negotiated TLS session:

C# 
                    public static void PrintSslConnectionInfo (string host, int port)
{
    using (var client = new SmtpClient ()) {
        client.Connect (host, port, SecureSocketOptions.Auto);

        Console.WriteLine ($"Negotiated the following SSL options with {host}:");
        Console.WriteLine ($"        Protocol Version: {client.SslProtocol}");
        Console.WriteLine ($"            Cipher Suite: {client.SslCipherSuite}");

        // Example Log:
        //
        // Negotiated the following SSL options with smtp.gmail.com:
        //         Protocol Version: Tls12
        //             Cipher Suite: TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256

        client.Disconnect (true);
    }
}

Configuring SSL/TLS

The following properties can be set before connecting to customize the TLS handshake:

  • SslProtocols: the SSL/TLS protocol versions that are allowed. On .NET (Core), the default (SslProtocols.None) lets the operating system choose the best available version, which is usually what you want. On .NET Framework, the default is the value of ServicePointManager.SecurityProtocol.

  • CheckCertificateRevocation: whether the server certificate's revocation status should be checked (the default is true).

  • ClientCertificates: client certificates to present to servers that require mutual TLS.

  • SslCipherSuitesPolicy: restricts the cipher suites that may be negotiated (only supported on some platforms).

C# 
                    public static void ConfigureTls ()
{
    using (var client = new ImapClient ()) {
        // Restrict the TLS protocol versions that may be negotiated.
        client.SslProtocols = SslProtocols.Tls12 | SslProtocols.Tls13;

        // Check the server certificate against the issuer's revocation list (this is the default).
        client.CheckCertificateRevocation = true;

        // Provide a client certificate if the server requires one.
        client.ClientCertificates = new X509CertificateCollection {
            new X509Certificate2 ("client.pfx", "password")
        };

        client.Connect ("imap.example.com", 993, SecureSocketOptions.SslOnConnect);

        client.Disconnect (true);
    }
}

Validating server certificates

By default, MailKit validates the server's certificate using the operating system's certificate store, just like a web browser. If validation fails, an SslHandshakeException is thrown whose message explains why the certificate was rejected.

To customize validation (for example, to accept a self-signed certificate for a specific internal server), set the ServerCertificateValidationCallback property before connecting. Be careful to only accept the specific certificate that you expect:

C# 
                    using System;
using System.Net.Security;
using System.Collections.Generic;
using System.Security.Cryptography.X509Certificates;

using MimeKit;
using MailKit;
using MailKit.Security;
using MailKit.Net.Smtp;

namespace MailKit.Examples
{
    public static class SslCertificateValidationExample
    {
        public static void SendMessage (MimeMessage message)
        {
            using (var client = new SmtpClient ()) {
                // Set our custom SSL certificate validation callback.
                client.ServerCertificateValidationCallback = MySslCertificateValidationCallback;

                // Connect to smtp.gmail.com on the SSL-wrapped port.
                client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);

                // Authenticate with our username and password.
                client.Authenticate ("username@gmail.com", "password");

                // Send our message.
                client.Send (message);

                // Disconnect cleanly from the server.
                client.Disconnect (true);
            }
        }

        static bool MySslCertificateValidationCallback (object sender, X509Certificate certificate, X509Chain chain, SslPolicyErrors sslPolicyErrors)
        {
            // If there are no errors, then everything went smoothly.
            if (sslPolicyErrors == SslPolicyErrors.None)
                return true;

            // Note: MailKit will always pass the host name string as the `sender` argument.
            var host = (string) sender;

            if ((sslPolicyErrors & SslPolicyErrors.RemoteCertificateNotAvailable) != 0) {
                // This means that the remote certificate is unavailable. Notify the user and return false.
                Console.WriteLine ("The SSL certificate was not available for {0}", host);
                return false;
            }

            if ((sslPolicyErrors & SslPolicyErrors.RemoteCertificateNameMismatch) != 0) {
                // This means that the server's SSL certificate did not match the host name that we are trying to connect to.
                var certificate2 = certificate as X509Certificate2;
                var cn = certificate2 != null ? certificate2.GetNameInfo (X509NameType.SimpleName, false) : certificate.Subject;

                Console.WriteLine ("The Common Name for the SSL certificate did not match {0}. Instead, it was {1}.", host, cn);
                return false;
            }

            // The only other errors left are chain errors.
            Console.WriteLine ("The SSL certificate for the server could not be validated for the following reasons:");

            // The first element's certificate will be the server's SSL certificate (and will match the `certificate` argument)
            // while the last element in the chain will typically either be the Root Certificate Authority's certificate -or- it
            // will be a non-authoritative self-signed certificate that the server admin created. 
            foreach (var element in chain.ChainElements) {
                // Each element in the chain will have its own status list. If the status list is empty, it means that the
                // certificate itself did not contain any errors.
                if (element.ChainElementStatus.Length == 0)
                    continue;

                Console.WriteLine ("\u2022 {0}", element.Certificate.Subject);
                foreach (var error in element.ChainElementStatus) {
                    // `error.StatusInformation` contains a human-readable error string while `error.Status` is the corresponding enum value.
                    Console.WriteLine ("\t\u2022 {0}", error.StatusInformation);
                }
            }

            return false;
        }
    }
}

  Caution

Never use a callback that simply returns true in production code. Doing so disables all protection against man-in-the-middle attacks.

Connecting through a proxy

To connect through a proxy server, set the ProxyClient property to one of the proxy clients in the MailKit.Net.Proxy namespace: HttpProxyClient, HttpsProxyClient, Socks4Client, Socks4aClient or Socks5Client.

C# 
                    public static void SendMessageViaProxy (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        client.ProxyClient = new Socks5Client ("socks5.proxy.com", 1080, new NetworkCredential ("proxyUserName", "proxyPassword"));
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);
        client.Authenticate ("username", "password");

        client.Send (message);

        client.Disconnect (true);
    }
}

The LocalEndPoint property can be used to bind the connection to a specific local IP address and/or port.

Timeouts and cancellation

The Timeout property (2 minutes by default) limits how long any single network read or write may take. It does not limit the total duration of an operation; to do that, pass a CancellationToken.

C# 
                    public static async Task ConnectWithTimeoutAsync ()
{
    using (var client = new ImapClient ()) {
        // The Timeout property (in milliseconds) applies to each individual network read and write.
        client.Timeout = 30 * 1000;

        // A CancellationToken can be used to put an upper bound on an entire operation.
        using (var cts = new CancellationTokenSource (TimeSpan.FromMinutes (2))) {
            await client.ConnectAsync ("imap.example.com", 993, SecureSocketOptions.SslOnConnect, cts.Token);
            await client.AuthenticateAsync ("username", "password", cts.Token);

            await client.Inbox.OpenAsync (FolderAccess.ReadOnly, cts.Token);
            Console.WriteLine ("The Inbox has {0} messages.", client.Inbox.Count);

            await client.DisconnectAsync (true, cts.Token);
        }
    }
}

  Note

Canceling a command that is in progress usually leaves the connection in an unknown state, so MailKit will disconnect. You will need to reconnect and re-authenticate before you can continue.

Logging the protocol

When something goes wrong, a protocol log is the most useful diagnostic tool available. Pass a ProtocolLogger to the client's constructor to log all of the commands and responses exchanged with the server:

C# 
                    public static void DownloadMessages ()
{
    using (var client = new ImapClient (new ProtocolLogger ("imap.log"))) {
        client.Connect ("imap.gmail.com", 993, SecureSocketOptions.SslOnConnect);

        client.Authenticate ("username", "password");

        client.Inbox.Open (FolderAccess.ReadOnly);

        var uids = client.Inbox.Search (SearchQuery.All);

        foreach (var uid in uids) {
            var message = client.Inbox.GetMessage (uid);

            // write the message to a file
            message.WriteTo (string.Format ("{0}.eml", uid));
        }

        client.Disconnect (true);
    }
}

By default, RedactSecrets is true, so passwords and authentication tokens are replaced with ******** in the log. Message contents are not redacted, so be careful when sharing logs. You can also implement IProtocolLogger yourself to route the output to your own logging framework.

Metrics and tracing

On .NET 8 and later, MailKit can emit metrics and traces using Meter and ActivitySource, which can be collected with OpenTelemetry. Enable them once at startup using the Telemetry class:

C# 
                    Telemetry.SmtpClient.Configure ();
Telemetry.Pop3Client.Configure ();
Telemetry.ImapClient.Configure ();

See Telemetry.md for the list of available metrics and traces.

Handling errors

The most common exceptions thrown by MailKit are:

  • SocketException: the host name could not be resolved or the connection was refused.

  • SslHandshakeException: the TLS handshake failed, usually because the server certificate could not be validated or because the client and server have no SSL/TLS protocol version in common.

  • AuthenticationException: the credentials were rejected.

  • CommandException (and the protocol-specific subclasses SmtpCommandException, Pop3CommandException and ImapCommandException): the server rejected a command. The connection is still usable.

  • ProtocolException (and subclasses): the server sent an unexpected response or the connection was dropped. The client will have been disconnected and must reconnect.

  • IOException: a network error occurred, including when the Timeout elapses during a synchronous operation (asynchronous operations throw a TimeoutException instead). The client will have been disconnected.

C# 
                    public static void SendMessage (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        try {
            client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);
        } catch (SmtpCommandException ex) {
            Console.WriteLine ("Error trying to connect: {0}", ex.Message);
            Console.WriteLine ("\tStatusCode: {0}", ex.StatusCode);
            return;
        } catch (SmtpProtocolException ex) {
            Console.WriteLine ("Protocol error while trying to connect: {0}", ex.Message);
            return;
        }

        // Note: Not all SMTP servers support authentication, but GMail does.
        if (client.Capabilities.Contains (SmtpCapability.Authentication)) {
            try {
                client.Authenticate ("username", "password");
            } catch (AuthenticationException ex) {
                Console.WriteLine ("Invalid user name or password.");
                return;
            } catch (SmtpCommandException ex) {
                Console.WriteLine ("Error trying to authenticate: {0}", ex.Message);
                Console.WriteLine ("\tStatusCode: {0}", ex.StatusCode);
                return;
            } catch (SmtpProtocolException ex) {
                Console.WriteLine ("Protocol error while trying to authenticate: {0}", ex.Message);
                return;
            }
        }

        try {
            client.Send (message);
        } catch (SmtpCommandException ex) {
            Console.WriteLine ("Error sending message: {0}", ex.Message);
            Console.WriteLine ("\tStatusCode: {0}", ex.StatusCode);

            switch (ex.ErrorCode) {
            case SmtpErrorCode.RecipientNotAccepted:
                Console.WriteLine ("\tRecipient not accepted: {0}", ex.Mailbox);
                break;
            case SmtpErrorCode.SenderNotAccepted:
                Console.WriteLine ("\tSender not accepted: {0}", ex.Mailbox);
                break;
            case SmtpErrorCode.MessageNotAccepted:
                Console.WriteLine ("\tMessage not accepted.");
                break;
            }
        } catch (SmtpProtocolException ex) {
            Console.WriteLine ("Protocol error while sending message: {0}", ex.Message);
        }

        client.Disconnect (true);
    }
}
