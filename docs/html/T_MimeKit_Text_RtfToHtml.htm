Remarks

Used to convert Rich Text Format (RTF) documents into HTML.

The converter implements the subset of the Rich Text Format (RTF) Specification, version 1.9.1, that can be meaningfully represented in HTML: character sets and code pages, Unicode escapes, paragraphs and paragraph alignment, line breaks, tables, bold, italic, underline, strikethrough, superscript, subscript, font sizes, foreground and background colors, and HYPERLINK fields. Destinations that do not contain document text (such as pictures, embedded objects, style sheets and document properties) are skipped, as is hidden text. The attachment placeholders (\objattph) that Microsoft Outlook and Exchange write are reported to the AttachmentPlaceholderCallback.

RTF documents that encapsulate HTML (such as those generated by Microsoft Outlook and Exchange), as described by [MS-OXRTFEX], have their original HTML extracted rather than having the RTF rendering of that HTML converted back into HTML. See ExtractEncapsulatedHtml.

The converter is designed to be resilient against hostile input. Its memory usage does not depend on the size of the input: font table, color table and group nesting resources are bounded by MaxFontTableEntries, MaxColorTableEntries and MaxGroupDepth, embedded binary data (\binN) is skipped without being buffered, and only hyperlinks with http, https, mailto, ftp or tel URL schemes are rendered as links.

  Note

Since RTF is a 7-bit format in which non-ASCII characters are escaped, the InputEncoding defaults to ISO-8859-1 so that every byte of the input maps to exactly one character. The code page used to decode escaped characters is determined by the document itself (\ansicpg, \fcharset and \cpg).

  Security Note

Encapsulated HTML is extracted as-is (subject to the HtmlTagCallback), exactly like HtmlToHtml would output it. RtfToHtml is not an HTML sanitizer. For displaying untrusted content, use a dedicated HTML sanitizer library.
