Sending messages with SMTP

SmtpClient is used to send messages created with MimeKit. This topic covers sending messages, controlling the envelope, handling rejected recipients, requesting delivery status notifications and other SMTP features.

For information about connecting securely, logging and error handling, see Connecting to a server. For information about authenticating, see Authentication.

Sending a message

The typical workflow is to connect, authenticate, send one or more messages and then disconnect:

C# 
                    public static void SendMessage (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);

        client.Authenticate ("username", "password");

        client.Send (message);

        client.Disconnect (true);
    }
}

Connecting and authenticating is relatively expensive, so if you have multiple messages to send, reuse the same connection for all of them rather than connecting once per message:

C# 
                    public static void SendMessages (IList<MimeMessage> messages)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);

        client.Authenticate ("username", "password");

        foreach (var message in messages) {
            client.Send (message);
        }

        client.Disconnect (true);
    }
}

  Note

SmtpClient is not thread-safe. To send messages concurrently, use one SmtpClient per thread (or a pool of clients).

Senders and recipients

Unless you specify otherwise, the SMTP envelope is derived from the message headers:

  • The envelope sender (MAIL FROM) is the Resent-Sender or first Resent-From mailbox if the message has been resent, otherwise the Sender or first From mailbox.

  • The envelope recipients (RCPT TO) are the mailboxes in the Resent-To, Resent-Cc and Resent-Bcc headers if the message has been resent, otherwise the mailboxes in the To, Cc and Bcc headers.

The Bcc and Resent-Bcc headers are never transmitted, so the other recipients cannot see them.

To use a different envelope (for example, to send a message to a different list of recipients than the ones listed in the headers), pass the sender and recipients explicitly using a SendRequest or SmtpSendRequest:

C# 
                    var request = new SmtpSendRequest (message, sender, recipients);

client.Send (request);

If the server supports the SMTPUTF8 extension, you can send messages that contain international (non-ASCII) email addresses and headers by enabling International:

C# 
                    public static void SendMessageWithOptions (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);

        client.Authenticate ("username", "password");

        var options = FormatOptions.Default.Clone ();

        if (client.Capabilities.Contains (SmtpCapability.UTF8))
            options.International = true;

        client.Send (options, message);

        client.Disconnect (true);
    }
}

Examining the result

Send returns a SendResult (an SmtpSendResult when using SmtpClient) containing the server's final response along with the lists of accepted and rejected recipients. Many servers include a queue identifier in the response text, which can be useful for tracking the message in the server's logs.

C# 
                    public static void SendMessage (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.example.com", 587, SecureSocketOptions.StartTls);
        client.Authenticate ("username", "password");

        var result = (SmtpSendResult) client.Send (new SmtpSendRequest (message));

        // The ResponseText is the server's final response to the DATA (or BDAT) command.
        // Many servers include a queue identifier that can be useful for tracking the message.
        Console.WriteLine ("{0}: {1}", result.StatusCode, result.ResponseText);

        foreach (var recipient in result.AcceptedRecipients)
            Console.WriteLine ("Accepted: {0}", recipient);

        client.Disconnect (true);
    }
}

Handling rejected recipients

By default, if the server rejects any of the recipients, an SmtpCommandException is thrown with an ErrorCode of RecipientNotAccepted and the message is not sent to anyone. The Mailbox property identifies the rejected recipient.

To deliver the message to the remaining recipients instead, subclass SmtpSendRequest and override OnRecipientNotAccepted(MailboxAddress, SmtpResponse) so that it does not throw. Rejected recipients are then listed in RejectedRecipients.

C# 
                    public class LenientSendRequest : SmtpSendRequest
{
    public LenientSendRequest (MimeMessage message) : base (message)
    {
    }

    public override void OnRecipientNotAccepted (MailboxAddress recipient, SmtpResponse response)
    {
        // Don't throw; the recipient will be listed in SendResult.RejectedRecipients instead.
        Console.WriteLine ("{0} was rejected: {1} {2}", recipient, response.StatusCode, response.ResponseText);
    }
}

public static void SendToAvailableRecipients (MimeMessage message)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.example.com", 587, SecureSocketOptions.StartTls);
        client.Authenticate ("username", "password");

        try {
            var result = client.Send (new LenientSendRequest (message));

            foreach (var recipient in result.RejectedRecipients)
                Console.WriteLine ("Not delivered to: {0}", recipient);
        } catch (SmtpCommandException ex) when (ex.ErrorCode == SmtpErrorCode.MessageNotAccepted) {
            // If *none* of the recipients were accepted, an SmtpCommandException is still thrown.
            Console.WriteLine ("None of the recipients were accepted.");
        }

        client.Disconnect (true);
    }
}

SmtpSendRequest also has OnSenderAccepted(MailboxAddress, SmtpResponse), OnSenderNotAccepted(MailboxAddress, SmtpResponse), OnRecipientAccepted(MailboxAddress, SmtpResponse) and OnNoRecipientsAccepted methods that can be overridden to observe each step of the transaction.

Delivery status notifications

If the server supports the DSN extension, you can ask it to notify the sender when a message is delivered, delayed or fails to be delivered to each recipient. Set the DeliveryStatusNotifications property (or override GetDeliveryStatusNotifications(MailboxAddress) to choose per recipient) and optionally an EnvelopeId that will be included in the notifications so that you can correlate them with the original message:

C# 
                    public static void SendWithDeliveryStatusNotifications (MimeMessage message)
{
    var request = new SmtpSendRequest (message) {
        // Since you will want to be able to map the envelope identifier back to the
        // message, the obvious identifier to use is probably the Message-Id value.
        EnvelopeId = message.MessageId,

        // Request that the server include only the headers of the original message
        // in any delivery status notifications that it sends back.
        DeliveryStatusNotificationType = DeliveryStatusNotificationType.HeadersOnly,

        // In this example, we only want to be notified of failures to deliver to a mailbox.
        // If you also want to be notified of delays or successful deliveries, simply bitwise-or
        // whatever combination of flags you want to be notified about.
        DeliveryStatusNotifications = DeliveryStatusNotification.Failure
    };

    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);
        client.Authenticate ("username", "password");

        var result = (SmtpSendResult) client.Send (request);

        Console.WriteLine ($"The server responded with: {result.StatusCode} {result.ResponseText}");

        client.Disconnect (true);
    }
}

public class PerRecipientSmtpSendRequest : SmtpSendRequest
{
    public PerRecipientSmtpSendRequest (MimeMessage message) : base (message)
    {
        EnvelopeId = message.MessageId;
    }

    /// <summary>
    /// Get the types of delivery status notification desired for the specified recipient mailbox.
    /// </summary>
    /// <remarks>
    /// Gets the types of delivery status notification desired for the specified recipient mailbox.
    /// </remarks>
    /// <returns>The desired delivery status notification type.</returns>
    /// <param name="recipient">The recipient mailbox.</param>
    public override DeliveryStatusNotification? GetDeliveryStatusNotifications (MailboxAddress recipient)
    {
        // Only request delivery status notifications for recipients outside of our domain.
        if (recipient.Domain.Equals ("example.com", StringComparison.OrdinalIgnoreCase))
            return DeliveryStatusNotification.Never;

        return DeliveryStatusNotification.Failure | DeliveryStatusNotification.Delay;
    }
}

Delivery status notifications arrive as ordinary messages in the sender's mailbox. See MessageDeliveryStatus for parsing them:

C# 
                    public void ProcessDeliveryStatusNotification (MimeMessage message)
{
    var report = message.Body as MultipartReport;

    if (report == null || report.ReportType == null || !report.ReportType.Equals ("delivery-status", StringComparison.OrdinalIgnoreCase)) {
        // this is not a delivery status notification message...
        return;
    }

    // process the report
    foreach (var mds in report.OfType<MessageDeliveryStatus> ()) {
        // process the status groups - each status group represents a different recipient

        // The first status group contains information about the message
        var envelopeId = mds.StatusGroups[0]["Original-Envelope-Id"];

        // all of the other status groups contain per-recipient information
        for (int i = 1; i < mds.StatusGroups.Length; i++) {
            var recipient = mds.StatusGroups[i]["Original-Recipient"];
            var action = mds.StatusGroups[i]["Action"];

            if (recipient == null)
                recipient = mds.StatusGroups[i]["Final-Recipient"];

            // the recipient string should be in the form: "rfc822;user@domain.com"
            var index = recipient.IndexOf (';');
            var address = recipient.Substring (index + 1);

            switch (action) {
            case "failed":
                Console.WriteLine ("Delivery of message {0} failed for {1}", envelopeId, address);
                break;
            case "delayed":
                Console.WriteLine ("Delivery of message {0} has been delayed for {1}", envelopeId, address);
                break;
            case "delivered":
                Console.WriteLine ("Delivery of message {0} has been delivered to {1}", envelopeId, address);
                break;
            case "relayed":
                Console.WriteLine ("Delivery of message {0} has been relayed for {1}", envelopeId, address);
                break;
            case "expanded":
                Console.WriteLine ("Delivery of message {0} has been delivered to {1} and relayed to the the expanded recipients", envelopeId, address);
                break;
            }
        }
    }
}

Server capabilities

After connecting, the Capabilities property lists the SMTP extensions supported by the server. MailKit automatically takes advantage of extensions such as PIPELINING, 8BITMIME, BINARYMIME and CHUNKING when they are available. MaxSize reports the maximum message size accepted by the server, if advertised.

C# 
                    public static void PrintCapabilities ()
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.gmail.com", 465, SecureSocketOptions.SslOnConnect);

        if (client.Capabilities.Contains (SmtpCapability.Authentication)) {
            var mechanisms = string.Join (", ", client.AuthenticationMechanisms);
            Console.WriteLine ("The SMTP server supports the following SASL mechanisms: {0}", mechanisms);
            client.Authenticate ("username", "password");
        }

        if (client.Capabilities.Contains (SmtpCapability.Size))
            Console.WriteLine ("The SMTP server has a size restriction on messages: {0}.", client.MaxSize);

        if (client.Capabilities.Contains (SmtpCapability.Dsn))
            Console.WriteLine ("The SMTP server supports delivery-status notifications.");

        if (client.Capabilities.Contains (SmtpCapability.EightBitMime))
            Console.WriteLine ("The SMTP server supports Content-Transfer-Encoding: 8bit");

        if (client.Capabilities.Contains (SmtpCapability.BinaryMime))
            Console.WriteLine ("The SMTP server supports Content-Transfer-Encoding: binary");

        if (client.Capabilities.Contains (SmtpCapability.UTF8))
            Console.WriteLine ("The SMTP server supports UTF-8 in message headers.");

        client.Disconnect (true);
    }
}

Some servers also support the VRFY and EXPN commands, which can be used to verify an address or expand a mailing list. Most public servers disable these commands to prevent address harvesting.

C# 
                    public static void VerifyAddress ()
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.mail-server.com", 465, SecureSocketOptions.SslOnConnect);
        client.Authenticate ("username", "password");

        try {
            var verified = client.Verify ("smith");
            Console.WriteLine ($"'smith' was resolved the the following mailbox: {verified}");
        } catch (SmtpCommandException ex) {
            Console.WriteLine ($"'smith' is not a valid address: {ex.Message}");
        }

        client.Disconnect (true);
    }
}
C# 
                    public static void ExpandAlias (string alias)
{
    using (var client = new SmtpClient ()) {
        client.Connect ("smtp.mail-server.com", 465, SecureSocketOptions.SslOnConnect);
        client.Authenticate ("username", "password");

        var expanded = client.Expand (alias);

        Console.WriteLine ($"Expanding the alias '{alias}' results in the following list of addresses:");
        foreach (var mailbox in expanded.Mailboxes)
            Console.WriteLine ($"* {mailbox}");

        client.Disconnect (true);
    }
}

Saving messages to a pickup directory

Some servers (such as IIS) pick up messages from a directory on disk rather than accepting them over the network. Messages written to a pickup directory must be "byte-stuffed" in the same way that they would be when sent using the DATA command. The SmtpDataFilter can be used to do this:

C# 
                    public static void SaveToPickupDirectory (MimeMessage message, string pickupDirectory)
{
    do {
        // Generate a random file name to save the message to.
        var path = Path.Combine (pickupDirectory, Guid.NewGuid ().ToString () + ".eml");
        Stream stream;

        try {
            // Attempt to create the new file.
            stream = File.Open (path, FileMode.CreateNew);
        } catch (IOException) {
            // If the file already exists, try again with a new Guid.
            if (File.Exists (path))
                continue;

            // Otherwise, fail immediately since it probably means that there is
            // no graceful way to recover from this error.
            throw;
        }

        try {
            using (stream) {
                // IIS pickup directories expect the message to be "byte-stuffed"
                // which means that lines beginning with "." need to be escaped
                // by adding an extra "." to the beginning of the line.
                //
                // Use an SmtpDataFilter to "byte-stuff" the message as it is written
                // to the file stream. This is the same process that an SmtpClient
                // would use when sending the message in a `DATA` command.
                using (var filtered = new FilteredStream (stream)) {
                    filtered.Add (new SmtpDataFilter ());

                    // Make sure to write the message in DOS (<CR><LF>) format.
                    var options = FormatOptions.Default.Clone ();
                    options.NewLineFormat = NewLineFormat.Dos;

                    message.WriteTo (options, filtered);
                    filtered.Flush ();
                    return;
                }
            }
        } catch {
            // An exception here probably means that the disk is full.
            //
            // Delete the file that was created above so that incomplete files are not
            // left behind for IIS to send accidentally.
            File.Delete (path);
            throw;
        }
    } while (true);
}
C# 
                    public static MimeMessage LoadFromPickupDirectory (string fileName)
{
    using (var stream = File.OpenRead (fileName)) {
        // IIS pickup directories store messages that have been "byte-stuffed"
        // which means that lines beginning with "." have been escaped by
        // adding an extra "." to the beginning of the line.
        //
        // Use an SmtpDataFilter to decode the message as it is loaded from
        // the file stream. This is the reverse process that an SmtpClient
        // would use when sending the message in a `DATA` command.
        using (var filtered = new FilteredStream (stream)) {
            filtered.Add (new SmtpDataFilter (decode: true));

            return MimeMessage.Load (filtered);
        }
    }
}
